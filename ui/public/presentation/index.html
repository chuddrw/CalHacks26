01 / Summary

Agent Cowork

Your agents finished.
Does their code work together?

Cowork checks work from your teammates’ coding agents before anyone commits. When the combined code fails, it sends the error and repair context to the assigned agent.

For developers working with agents on separate laptops.
Here’s the problem ↓

02 / Problem

Git merges it.
The app still breaks.

One agent changes an API. Another writes code that expects the old behavior. Both finish their tasks, but someone on the team has to figure out why the app no longer works.

Agent A

Switches to milliseconds

Changes the units stored in lastLogin.

Agent B

Still expects seconds

Uses that timestamp to calculate how long someone has been idle.

This is our controlled demo scenario. The agents edit different files, so Git reports no conflict. Both values are numbers; the integration test catches the unit mismatch.

03 / Solution

Check their work together
while they’re still coding.

Agents share what they plan to change. Cowork also runs their latest code together, so the team can catch mistakes the plans didn’t account for.

  1. 01

    Save the work in progress

    Each laptop pushes a snapshot to its own WIP branch. The developer doesn’t need to make a feature commit.

  2. 02

    Run the combined code

    The watcher brings those snapshots into a temporary worktree and runs the project’s checks.

  3. 03

    Give the fixer the error

    When a check fails, Cowork records the conflict and sends the assigned agent the diagnosis.

  4. 04

    Check the next snapshot

    After a repair, the watcher runs again. The team sees whether the combined tests pass.

06 / Technical details

What runs where?

On each laptop

Hooks + MCP

Hooks push snapshots to GitHub branches named wip/<agent>. Through MCP, an agent can share its plans and read updates from teammates.

Integration

Watcher + checks

The watcher combines snapshots with main in a temporary worktree. It runs TypeScript and Vitest, then checks individual agents and pairs to narrow down a failure.

Shared state

SpacetimeDB

SpacetimeDB stores the team’s live state. Creating a conflict, assigning its fixer, and notifying the agents happen in one transaction. Subscribers receive the updates.

What the team sees

Diagnosis + dashboard

Droid investigates the failure. The dashboard shows its explanation beside the test output, along with who is fixing it and whether a person needs to review the changes.

A passing check covers the behavior the tests exercise. Cowork doesn’t automatically merge the result into main.
